# ADR 0002 — Better Auth CLI package rename (`@better-auth/cli` → `auth`)

Date: 2026-11-06 · Phase 03 · Status: accepted

## Context

Task 03 planned `pnpm dlx @better-auth/cli generate`. Every stable version of
`@better-auth/cli` on npm (latest 1.4.21, release-1.4 1.4.22) is marked
_deprecated — "Package no longer supported"_, and pulls an old better-auth 1.4
tree. The official docs (better-auth.com/docs/concepts/cli) now use an
unscoped package simply named `auth` (`pnpm dlx auth@latest generate`), same
repo (github.com/better-auth/better-auth) and maintainer — verified with
`pnpm view`.

## Decision

- Do **not** install any CLI as a devDependency. Run schema generation as
  `pnpm dlx auth@latest generate --config src/lib/auth/server.ts --output /tmp/…`
  for reference/cross-checks only.
- `src/db/schema.ts` remains the single source of truth. The auth tables were
  hand-written (Better Auth 1.7.18 core field shapes read from the installed
  package's zod schemas) and diffed against the CLI reference output:
  fields match 1:1; deliberate divergences are uuid PKs with `defaultRandom`,
  `timestamptz` everywhere, table renames (`sessions`, `accounts_auth`,
  `verifications`), and domain FKs/indexes idiom.

## Consequences

- Migrations are generated by drizzle-kit (0001 adds the auth tables), not by
  the Better Auth CLI — consistent with the rest of the schema pipeline.
- Future Better Auth upgrades re-run the CLI cross-check before touching auth
  tables.
